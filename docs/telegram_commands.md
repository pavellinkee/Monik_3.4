# MONIK — КОМАНДЫ TELEGRAM

> Техническая документация. Архитектурные документы в `docs/architecture/`
> этим файлом **не изменяются** (`CLAUDE.md` §43).

Управление Monik выполняется из Telegram: командой текстом или кнопкой.
Кнопка и команда делают одно и то же — второй модели ввода нет.

Канал команд включается настройкой `notifications.telegram.commands_enabled`
и работает только для чата, заданного `notifications.telegram.chat_id`.
Сообщения из других чатов игнорируются.

---

## 1. Быстрый старт

Отправьте боту:

```
/menu
```

Появится сообщение с кнопками управления. Дальше можно пользоваться
только кнопками — команды знать не обязательно.

Полный список команд с пояснениями:

```
/help
```

## 2. Полный список команд

| Команда | Кнопка | Назначение | Что возвращает | Подтверждение |
|---|---|---|---|---|
| `/menu` | — | показать кнопки управления | сообщение с клавиатурой и текущим состоянием сканера | нет |
| `/help` | ❓ Помощь | список команд | перечень команд с назначением | нет |
| `/status` | 📊 Статус | состояние приложения целиком | версия, окружение, состояние сканера, подсистемы, очереди агрегаторов | нет |
| `/providers` | 🔌 Статус агрегатора | состояние агрегаторов | строка на каждый агрегатор + кнопки выбора одного | нет |
| `/providers <имя>` | кнопка агрегатора | состояние одного агрегатора | health, circuit breaker, лимит частоты, загрузка очереди, причина деградации | нет |
| `/scans` | 🕔 Последние сканы | последние циклы Level 1 | до 5 циклов: время, статус, число запросов, успешных, возможностей | нет |
| `/level2` | 🧪 Level 2 | активные проверки Level 2 | список `#K` со статусом и числом попыток | нет |
| `/details K1234` | кнопка `об` | результат конкретной проверки | сохранённый результат по суммам | нет |
| `/stats` | 📈 Статистика | накопленная статистика | циклы, возможности, уведомления, confirmation rate | нет |
| `/backup` | 💾 Резервные копии | состояние резервного копирования | число копий, время и итог последнего запуска, каталог | нет |
| `/start` | ▶️ Запустить | разрешить сканирование | подтверждение изменения состояния | нет |
| `/stop` | ⏸ Остановить | остановить сканирование | **запрос подтверждения** | **да** |
| `/restart` | 🔄 Перезапустить | перезапустить приложение | **запрос подтверждения** | **да** |
| `/update` | ⬇️ Обновить и перезапустить | установить обновления системы и перезапустить Monik | **запрос подтверждения** | **да** |

Значения `<имя>` для `/providers`: `zero_x`, `velora`, `uniswap` — то
есть идентификаторы включённых провайдеров из конфигурации.

## 3. Действия, требующие подтверждения

Три команды прерывают работу сканера, поэтому выполняются в два шага:

- `/stop` — **Остановить**
- `/restart` — **Перезапустить**
- `/update` — **Обновить и перезапустить**

Первый шаг показывает вопрос и две кнопки: **✅ Да** и **↩️ Отмена**.
Действие выполняется только после нажатия **✅ Да**. Отмена возвращает в
меню и ничего не меняет.

Случайное нажатие или случайно отправленная команда не остановят
production.

---

## 4. Что означает каждое управляющее действие

### ▶️ Запустить (`/start`)

Разрешает начинать новые циклы Level 1. Если сканирование уже идёт,
состояние не меняется и приходит соответствующий ответ.

### ⏸ Остановить (`/stop`)

Запрещает начинать **новые** циклы Level 1.

Что при этом **не** происходит:

- уже принятые проверки Level 2 не прерываются и доводятся до конца —
  прерывать безопасную операцию ради освобождения ресурса нельзя
  (`05_RESOURCE_MANAGER.md` §18);
- приложение не завершается: Telegram, диагностика и команды продолжают
  работать;
- уже сформированные уведомления продолжают доставляться.

Состояние хранится в памяти процесса. После перезапуска приложения
сканирование снова разрешено: иначе одна команда «Остановить» тихо
выключила бы сканер навсегда.

### 🔄 Перезапустить (`/restart`)

Корректно завершает работу и останавливает процесс с кодом возврата `3`.

**Поднимает процесс обратно менеджер служб, а не приложение.** Команда
работает только если служба настроена на автоматический перезапуск:

```ini
[Service]
Restart=always
```

Без этой настройки команда просто остановит Monik. Проверить настройку
можно до использования команды — см. `docs/OPERATING.md`.

### ⬇️ Обновить и перезапустить (`/update`)

Устанавливает доступные обновления операционной системы и после этого
перезапускает Monik. Кнопка появляется в ежедневном уведомлении о
доступных обновлениях; командой `/update` то же действие доступно в
любой момент.

Порядок выполнения:

1. обновляется список пакетов;
2. устанавливаются обновления — неинтерактивно, существующие файлы
   настроек остаются нетронутыми;
3. только при успешной установке запрашивается перезапуск приложения.

Пока идёт установка, приложение не отвечает на другие команды: установка
занимает несколько минут. Если установить не удалось, перезапуск **не**
запрашивается — терять цикл сканирования незачем, а причина приходит
ответным сообщением.

**Право требуется системное, а не настройка Monik.** Приложение
выполняет установку через `sudo -n`, то есть без запроса пароля. Если
такое право не выдано, кнопка в уведомлении не появляется, а команда
отвечает «нет права выполнять установку без пароля». Как выдать право
ровно на эту операцию — см. `docs/OPERATING.md`.

## 5. Что показывает `/status`

- версия приложения и окружение (`development` / `test` / `production`);
- состояние сканера: идёт, остановлен оператором, запрошен перезапуск;
- состояние подсистем: `configuration`, `database`, `resource_manager`,
  `scheduler`, `level1`, `level2`, `fees`, `calculator`, `notifications`;
  у `level1` в скобках указано время последнего цикла;
- состояние провайдеров с причиной деградации (нормализованный код
  ошибки, не текст ответа API);
- очереди агрегаторов: сколько запросов выполняется, сколько ожидает,
  какой лимит частоты применён.

`/status` **никогда** не показывает API-ключи, bot token, chat id,
приватные ключи и содержимое ответов провайдеров
(`19_HEALTH_MONITORING.md` §65, `15_NOTIFICATION_SYSTEM.md` §70-71).

---

## 6. Что показывает `/stats`

Значения накапливаются **с момента запуска процесса** и обнуляются при
перезапуске: они читаются из реестра метрик, который живёт в памяти.

- циклов Level 1;
- возможностей создано;
- уведомлений отправлено;
- подтверждённых, не подтверждённых и неопределённых сумм;
- confirmation rate по формуле `CLAUDE.md` §27 — `PARTIAL` в расчёт не
  входит, при отсутствии решений показывается `N/A`.

---

## 7. Кнопка `об`

Кнопка `об` присутствует в **каждом** уведомлении о возможности
(`CLAUDE.md` §35). Нажатие показывает сохранённый текст подробностей и
**не выполняет нового запроса к API**.

Эта кнопка не относится к меню управления и живёт отдельно от него.

---

## 8. Ограничения

- команды принимаются только из настроенного чата; сообщения из других
  чатов игнорируются и записываются в лог как отклонённые;
- Telegram обрабатывается отдельной задачей планировщика и **не
  блокирует** сканер (`CLAUDE.md` §35);
- очередь Telegram отделена от очередей агрегаторов: уведомления и
  команды не расходуют лимиты провайдеров;
- команда, отправленная во время недоступности Telegram API, будет
  обработана после восстановления связи — обновления доставляются
  как минимум один раз, повторы отбрасываются по `update_id`;
- `/details` требует идентификатор вида `K1234`; без него приходит
  подсказка, а не ошибка;
- управляющие кнопки показываются только если канал команд настроен и
  доступно управление сканером.

---

## 9. Уведомления, приходящие без запроса

Помимо ответов на команды Monik присылает:

- **🟢 / 🟠 / 🔴 сообщение о запуске** — после проверки готовности, с
  версией, окружением, сетью, провайдерами и состоянием подсистем.
  Различаются первый запуск, перезапуск и запуск после аварии;
- **уведомления о возможностях** — только подтверждённые Level 2, с
  кнопкой `об`;
- **изменения состояния** — деградация и восстановление провайдера или
  подсистемы. Повторы одного состояния объединяются: сотня одинаковых
  ошибок даёт одно сообщение и периодическую сводку вида
  «всё ещё unavailable — 137 ошибок с прошлого уведомления».

Успешная штатная работа уведомлений не создаёт.
